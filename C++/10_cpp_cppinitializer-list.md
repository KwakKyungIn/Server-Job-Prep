# 🧩 C++ 초기화 리스트 정리 (`Initializer List`)

> 이 문서는 C++ 클래스의 **멤버 초기화 방식** 중 하나인 `초기화 리스트`에 대해 정리한 문서입니다.  
> 생성자 본문에서 대입하는 것과 초기화 리스트로 직접 초기화하는 것의 차이, 성능, 코드 구조적 측면에서의 장단점을 살펴봅니다.

---

## ❓ 초기화 리스트란?

```cpp
class Example {
    int a;
    double b;
public:
    Example(int x, double y) : a(x), b(y) {
        // 생성자 본문은 비어 있어도 됨
    }
};
```

- `: a(x), b(y)` 부분이 바로 **초기화 리스트**입니다.
- 생성자 본문이 실행되기 전에, 멤버들을 지정된 값으로 초기화합니다.

---

## ✅ 왜 초기화 리스트를 써야 할까?

| 이유 | 설명 |
|------|------|
| 🔹 필수 초기화가 필요한 타입 | `const`, `reference` 멤버는 초기화 리스트 없이는 초기화 불가능 |
| 🔹 성능 | 생성자 본문에서 대입하면 **기본 생성자 + 대입자 호출** → 비효율 |
| 🔹 명확성 | 멤버가 어떤 순서로 초기화되는지 명확히 드러남 |
| 🔹 복잡한 타입 초기화 | 복사/이동이 비싼 객체(ex. STL container, 객체 포함 시)는 리스트가 필수에 가까움 |

```cpp
class Test {
    const int x;       // 반드시 초기화 리스트로 초기화
    int& ref;          // 참조도 마찬가지

public:
    Test(int val, int& r) : x(val), ref(r) { }
};
```

---

## 🏗️ 포함관계 vs 상속관계에서의 초기화 리스트

초기화 리스트는 **구성(composition)** 과 **상속(inheritance)** 구조 모두에서 중요하지만, **순서**나 **초기화 책임** 측면에서 다르게 작용합니다.

### 📦 포함 관계 (has-a)

```cpp
class Engine {
public:
    Engine(int power) { /* ... */ }
};

class Car {
    Engine engine;
public:
    Car(int p) : engine(p) { } // 초기화 리스트로 포함 객체 초기화
};
```

- 포함된 멤버 객체는 초기화 리스트에서 직접 생성됨
- 생성자 본문에서 생성하면 **기본 생성 → 다시 대입**이 발생

### 🧬 상속 관계 (is-a)

```cpp
class Animal {
public:
    Animal(int age) { /* ... */ }
};

class Dog : public Animal {
public:
    Dog(int age) : Animal(age) { } // 부모 클래스는 반드시 초기화 리스트로!
};
```

- **부모 클래스 생성자는 반드시 초기화 리스트에서 명시적으로 호출**해야 함
- 호출하지 않으면 **기본 생성자**가 자동 호출됨 → 의도치 않은 동작

---

## 🔁 멤버 초기화 순서의 주의점

> 💡 초기화 리스트에 적은 순서와 실제 초기화 순서는 **다르다**!

- 실제 초기화 순서는 **멤버가 클래스에 정의된 순서**를 따른다.
- 예시:

```cpp
class Foo {
    int a;
    int b;
public:
    Foo() : b(2), a(1) { } // 정의 순서와 다름 → 경고 가능성
};
```

- 위 예시에서 실제 초기화 순서는 `a → b` 순서로 진행됨.
- 초기화 리스트 순서와 일치하지 않으면 **컴파일러가 경고를 줄 수 있음**.

---

## 🚫 초기화 리스트를 안 쓰면 생기는 문제

| 상황 | 문제 |
|------|------|
| `const` 멤버 | 값을 못 바꾸기 때문에 생성자 본문에서 대입 불가 |
| `reference` 멤버 | 참조는 선언과 동시에 초기화되어야 하므로 리스트 필수 |
| STL 포함 멤버 | 기본 생성 후 대입은 복사/이동 비용 발생 |

## ✅ 요약

| 구분 | 리스트 초기화 필요 여부 | 설명 |
|------|--------------------------|------|
| `const` 멤버 | ✅ 필수 | 생성자 본문에선 불가능 |
| `reference` 멤버 | ✅ 필수 | 선언과 동시에 초기화 |
| 기본 타입 멤버 | ⭕ 권장 | 성능 향상 |
| 포함된 객체 | ⭕ 권장 | 명시적 초기화로 복사 비용 감소 |
| 상속된 부모 클래스 | ✅ 필수 | 부모 생성자 호출은 리스트에서만 가능 |

---

> 🔧 정리하자면, 초기화 리스트는 단순한 문법 요소가 아니라 **성능, 안전성, 정확한 객체 구성**을 위한 핵심입니다.
