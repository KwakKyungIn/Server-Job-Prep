# 💥 크래시 일관성: FSCK와 저널링 (OSTEP Chapter 45)

> 이 장에서는 시스템 크래시나 전력 손실과 같은 비정상 종료 상황에서  
> **디스크 자료 구조의 일관성을 유지하는 방법**을 설명한다.  
> FSCK(파일 시스템 검사기)와 저널링(Journaling), 기타 고급 기법까지 다룬다.

---

## ❓ 핵심 질문

> 시스템이 갑자기 꺼졌을 때,  
> **디스크 상의 자료 구조는 어떻게 손상되지 않도록 보호할 수 있을까?**  
> 전원이 복구된 후, 파일 시스템은 어떻게 "정상 상태"로 돌아갈 수 있을까?

---

## 🔍 상세 개념 정리

### 45.1 예제: 단순 파일 쓰기에서 발생 가능한 크래시

- 파일 끝에 4KB 블록을 추가하는 연산
- 필요한 디스크 자료 구조 갱신:
  - 아이노드 (`I[v2]`)
  - 데이터 비트맵 (`B[v2]`)
  - 새 데이터 블록 (`Db`)
- 쓰기 순서에 따라 다양한 **불일치 시나리오** 발생 가능:
  - 일부 블록만 기록되고 크래시 → 메타데이터와 실제 데이터 불일치

---

### 45.2 해법 1: FSCK (파일 시스템 검사기)

- 전통적인 Unix 시스템의 방식
- 크래시 후 전체 파일 시스템을 스캔하여 일관성 복구
- 대표 도구: `fsck` (file system check)
- 동작 단계 요약:
  - 슈퍼블록 검사
  - 블록/아이노드 비트맵 검사 및 재생성
  - 아이노드 유효성 확인 및 초기화
  - 디렉터리 트리 순회하여 링크 개수 확인
  - 중복 포인터 탐지, 배드 블록 제거
  - 디렉터리 구조 점검 (".", "..", 이중 참조 등)

❗ **단점**: 매우 느리다. → 대용량 시스템에서 실용성 부족

---

### 45.3 해법 2: 저널링 (Journaling)

> Write-Ahead Logging(WAL)을 파일 시스템에 적용한 기법

#### ✅ 기본 아이디어
- 실제 데이터 변경 전에 **수행할 작업을 로그로 저장**
- 크래시 발생 시 로그만 보고 **복구 (replay)** 가능

#### 🔄 절차
1. **저널 기록**: 트랜잭션 시작 블록, 변경될 블록들, 종료 블록(TxE) 기록
2. **저널 커밋**: TxE가 기록되면 → "성공적인 트랜잭션" 간주
3. **체크포인트**: 변경된 블록들을 실제 위치에 기록
4. **프리 처리**: 로그 공간 회수 (저널 슈퍼블록 갱신)

#### 📌 트랜잭션 커밋 조건
- **TxE는 원자적으로** 기록되어야 함
- 반드시 모든 변경 블록 기록 완료 후 TxE 쓰기

---

#### 📌 두 가지 모드

##### ▶ 데이터 저널링 (Data Journaling)
- **모든 데이터와 메타데이터**를 로그에 기록
- 안전하지만 느림 (디스크 I/O 2배)

##### ▶ 메타데이터 저널링 (Ordered Journaling)
- **메타데이터만** 로그에 기록
- 데이터는 디스크의 최종 위치에 직접 저장
- 메타데이터 → 반드시 **데이터보다 나중에 기록**

---

#### 💡 기타 최적화 기법
- 체크섬을 활용한 트랜잭션 무결성 검증
- 로그 버퍼링 및 일괄 처리 → I/O 트래픽 감소
- 순서를 보장하는 쓰기 배리어 (`write barrier`)

---

### 45.4 해법 3: 그 외 방법들

#### ▶ Soft Updates
- **모든 쓰기 순서를 엄격히 제어**하여 일관성 보장
- 고성능, 낮은 쓰기 횟수
- 구현이 매우 복잡함

#### ▶ Copy-On-Write (COW)
- 기존 블록을 절대 덮어쓰지 않고 **새 위치에 복사 후 갱신**
- ex) ZFS, btrfs

#### ▶ Backpointer-based Consistency
- 모든 블록에 **역방향 포인터** 추가
- 포인터 간 상호 참조로 일관성 검증 가능

#### ▶ Optimistic Crash Consistency
- 최대한 큰 단위로 디스크 쓰기
- 트랜잭션 체크섬으로 오류 감지

## ✅ 요약 정리

| 기법 | 설명 | 장점 | 단점 |
|------|------|------|------|
| **FSCK** | 시스템 부팅 시 전체 검사 | 간단 | 느림 |
| **저널링** | 사전 기록 + 복구 | 빠름, 신뢰성 ↑ | 쓰기 오버헤드 |
| **Soft Updates** | 쓰기 순서 제어로 보장 | 성능 ↑ | 복잡 |
| **COW** | 복사 후 포인터 변경 | 신뢰성 ↑ | 공간 사용 ↑ |
| **Backpointer** | 블록 간 상호 참조 | 정확한 검증 | 설계 복잡 |
| **Optimistic** | 체크섬 기반 검증 | 성능 ↑ | 디스크 지원 필요 |
