# Game Math Guide for Written Test Preparation

이 문서는 게임 프로그래머 필기시험을 준비할 때 필요한 게임 수학을 **기초부터 심화까지 한 번에 복습할 수 있도록** 정리한 학습 자료입니다. 목표는 단순 공식 암기가 아니라, 각 개념이 실제 게임 코드와 어떤 연결을 가지는지 이해하는 것입니다.

---

## 0. 학습 가이드

- 이 문서는 `기초 산술/기하 -> 벡터/행렬 -> 회전/변환 -> 충돌/카메라 -> 확률/수치해석` 순서로 읽는 것을 권장합니다.
- 필기시험에서는 “정의”, “의미”, “계산”, “실전 적용”이 함께 나옵니다.
- 특히 게임 수학은 다음 질문으로 정리하면 기억이 오래갑니다.
  - 이 수식은 무엇을 계산하는가?
  - 입력과 출력의 단위는 무엇인가?
  - 게임에서 언제 쓰이는가?
  - 어떤 예외 상황에서 깨지는가?

---

## 1. 수학적 기초 체력

### 1.1 스칼라와 변수

- **스칼라(scalar)**는 크기만 있는 값입니다.
- 예: 시간 `t`, 질량 `m`, 속력 `speed`, 체력 `hp`
- 벡터와 달리 방향이 없습니다.

게임에서 자주 쓰는 스칼라:

- 거리
- 속력
- 각도
- 확률
- 쿨다운 시간
- 데미지 계수

### 1.2 절댓값, 제곱, 제곱근

- `|x|`는 절댓값입니다.
- `x^2`는 제곱입니다.
- `sqrt(x)`는 제곱근입니다.

자주 쓰는 이유:

- 거리 계산
- 길이 계산
- 오차 비교
- 분산, 표준편차 계산

예:

- 2차원 점 `(x1, y1)`와 `(x2, y2)` 사이 거리:
  - `d = sqrt((x2 - x1)^2 + (y2 - y1)^2)`

### 1.3 비율과 정규화된 값

- 많은 게임 시스템은 실제 값을 `0~1` 범위로 정규화해서 다룹니다.
- 예:
  - 체력 비율 = `currentHp / maxHp`
  - 진행도 = `elapsed / duration`
  - 입력 세기 = `inputMagnitude / maxMagnitude`

주의:

- 분모가 0일 수 있는지 항상 확인해야 합니다.
- 정수 나눗셈과 실수 나눗셈을 혼동하면 결과가 틀어집니다.

### 1.4 함수와 그래프 감각

필기시험에서 그래프 해석이 종종 중요합니다.

- 선형 함수: `y = ax + b`
  - 일정한 증가/감소
  - 예: 경험치 보너스, 선형 보간
- 2차 함수: `y = ax^2 + bx + c`
  - 포물선
  - 예: 탄도 운동
- 지수 함수: `y = a^x`
  - 빠른 증가/감소
  - 예: 난이도 곡선, 감쇠
- 삼각 함수: `sin`, `cos`
  - 주기 운동
  - 예: 흔들림, 진동, 파동

## 2. 기하와 삼각함수

### 2.1 각도와 라디안

- 각도(degree): 1바퀴 = `360도`
- 라디안(radian): 1바퀴 = `2π`
- 변환:
  - `radian = degree * π / 180`
  - `degree = radian * 180 / π`

게임 코드에서는 대부분 라디안을 사용합니다.

이유:

- 미분/적분에서 자연스럽습니다.
- 삼각함수 표준 라이브러리 입력이 라디안인 경우가 많습니다.

### 2.2 sin, cos, tan의 의미

직각삼각형 기준:

- `sinθ = 높이 / 빗변`
- `cosθ = 밑변 / 빗변`
- `tanθ = 높이 / 밑변`

단위원 기준:

- `cosθ`는 x좌표
- `sinθ`는 y좌표

게임에서 쓰는 예:

- 방향 벡터 생성
- 원운동
- 탄도 분해
- 회전 행렬
- 시야각 계산

### 2.3 피타고라스 정리

- `a^2 + b^2 = c^2`

게임에서 매우 자주 사용됩니다.

- 벡터 길이
- 거리 계산
- 속도 성분 합성
- 충돌 반경 계산

### 2.4 삼각함수와 좌표 이동

길이 `r`, 각도 `θ`인 방향으로 이동할 때:

- `x = r cosθ`
- `y = r sinθ`

예:

- 플레이어가 바라보는 방향으로 발사체 생성
- 카메라를 원 궤도로 회전

### 2.5 역삼각함수

- `asin`, `acos`, `atan`, `atan2`

특히 `atan2(y, x)`가 중요합니다.

이유:

- x, y 부호를 모두 고려해 올바른 사분면의 각도를 반환합니다.
- 단순 `atan(y/x)`는 분모가 0일 때 위험하고 사분면 정보가 깨집니다.

예:

- 대상 방향으로 캐릭터 회전
- 마우스 위치를 향한 각도 계산

## 3. 벡터

### 3.1 벡터란 무엇인가

- 벡터는 **크기와 방향을 함께 가진 값**입니다.
- 2D 예: `(x, y)`
- 3D 예: `(x, y, z)`

게임에서 벡터로 표현하는 것:

- 위치
- 방향
- 속도
- 가속도
- 힘
- 법선
- 조명 방향

### 3.2 벡터 덧셈과 뺄셈

- `a + b`: 두 효과를 합침
- `a - b`: 한 점에서 다른 점까지의 방향

예:

- `target - position`은 현재 위치에서 목표까지 향하는 벡터입니다.

### 3.3 스칼라배

- `k * v`
- 벡터 방향은 유지하고 크기만 바꿉니다.

예:

- 속도 벡터에 시간 `dt`를 곱해 프레임 이동량 계산

### 3.4 길이와 정규화

벡터 `v = (x, y, z)`의 길이:

- `|v| = sqrt(x^2 + y^2 + z^2)`

정규화(normalize):

- 길이를 1로 만드는 것
- `v_hat = v / |v|`

주의:

- 길이가 0인 벡터는 정규화할 수 없습니다.
- `epsilon` 검사 없이 정규화하면 NaN이 날 수 있습니다.

게임에서 정규화가 필요한 경우:

- 이동 방향
- 시선 방향
- 조명 방향
- 투영 계산

### 3.5 내적(dot product)

벡터 `a`, `b`의 내적:

- `a · b = ax * bx + ay * by + az * bz`
- `a · b = |a||b|cosθ`

의미:

- 두 벡터가 얼마나 같은 방향을 향하는지
- 한 벡터를 다른 벡터 방향으로 얼마나 투영할 수 있는지

판단 기준:

- 양수: 비슷한 방향
- 0: 수직
- 음수: 반대 방향

게임 활용:

- 시야 판정
- 조명 밝기 계산
- 전후방 판정
- 표면을 따라 미끄러지는 방향 계산

예:

- 적이 플레이어 앞에 있는지:
  - `forward · toTarget > 0`

### 3.6 외적(cross product)

3차원 벡터 `a`, `b`의 외적:

- `a x b`

의미:

- `a`와 `b` 둘 다에 수직인 벡터
- 크기는 `|a||b|sinθ`

게임 활용:

- 법선 벡터 계산
- 회전축 계산
- 오른손/왼손 좌표계 판단
- 삼각형 면의 앞뒤 판정

주의:

- 외적 순서를 바꾸면 방향이 반대가 됩니다.
- `a x b = -(b x a)`

### 3.7 벡터 투영

벡터 `a`를 `b` 위로 투영:

- `proj_b(a) = (a · b / |b|^2) b`

`b`가 단위 벡터라면:

- `proj_b(a) = (a · b) b`

게임 활용:

- 표면 위 이동 성분만 남기기
- 카메라 기준 전진/측면 성분 분리
- 속도를 법선 방향과 접선 방향으로 분해

### 3.8 벡터 분해

속도 `v`를 법선 `n`과 접선 방향으로 나누면:

- 법선 성분: `vn = (v · n) n`
- 접선 성분: `vt = v - vn`

게임 물리와 충돌 응답에서 매우 중요합니다.

## 4. 좌표계와 공간 감각

### 4.1 좌표계의 종류

게임에서는 여러 공간을 계속 오갑니다.

- Local Space
  - 객체 자신의 기준 좌표계
- World Space
  - 세계 전체의 기준 좌표계
- View Space
  - 카메라 기준 좌표계
- Clip Space
  - 투영 후 잘라내기 전 좌표계
- Screen Space
  - 실제 화면 좌표

### 4.2 기준축(basis) 이해

3차원 공간에서 보통 세 개의 기준축을 씁니다.

- Right
- Up
- Forward

이 세 축은 객체의 방향을 나타냅니다.

게임에서 “캐릭터가 바라보는 방향”은 보통 forward 축입니다.

### 4.3 좌표 변환의 핵심 아이디어

좌표 변환은 “한 기준에서 본 점을 다른 기준으로 다시 표현”하는 작업입니다.

예:

- 손(Local) 위치를 캐릭터(World) 좌표로 변환
- 월드 좌표를 카메라(View) 좌표로 변환

### 4.4 아핀 변환

게임에서 자주 쓰는 변환:

- 이동(translation)
- 회전(rotation)
- 크기변환(scale)
- 전단(shear)

대부분 게임에서는 이동 + 회전 + 스케일이 핵심입니다.

## 5. 행렬

### 5.1 행렬이 필요한 이유

행렬은 선형 변환을 깔끔하게 표현합니다.

장점:

- 여러 변환을 하나로 합칠 수 있음
- 좌표 변환을 일관되게 처리 가능
- GPU 파이프라인과 잘 맞음

### 5.2 2D 회전 행렬

각도 `θ`만큼 회전:

- `x' = x cosθ - y sinθ`
- `y' = x sinθ + y cosθ`

행렬 형태:

```text
[ cosθ  -sinθ ]
[ sinθ   cosθ ]
```

### 5.3 3D 변환 행렬

3D 게임에서는 보통 4x4 행렬을 씁니다.

이유:

- 이동까지 포함하려면 동차좌표(homogeneous coordinates)가 필요합니다.

### 5.4 동차좌표

- 점(position): `(x, y, z, 1)`
- 방향(direction): `(x, y, z, 0)`

이 차이가 중요합니다.

이유:

- 점은 이동의 영향을 받습니다.
- 방향은 이동의 영향을 받지 않습니다.

### 5.5 변환 순서

보통 `Scale -> Rotation -> Translation` 순서가 자주 등장합니다.

주의:

- 행렬 곱셈은 교환법칙이 성립하지 않습니다.
- 즉, `AB != BA`인 경우가 대부분입니다.
- 엔진이 row-major인지 column-major인지, 벡터를 왼쪽에 곱하는지 오른쪽에 곱하는지에 따라 코드 형태가 달라집니다.

시험 포인트:

- “변환 순서가 결과를 바꾸는 이유”를 설명할 수 있어야 합니다.

### 5.6 역행렬

역행렬은 “변환을 되돌리는 행렬”입니다.

활용:

- 월드 좌표를 로컬 좌표로 되돌리기
- View 행렬 만들기
- 법선 변환의 기반 이해

예:

- 카메라의 View 행렬은 카메라 월드 변환의 역변환으로 볼 수 있습니다.

### 5.7 전치행렬과 직교행렬

- 전치(transpose): 행과 열을 바꿈
- 직교행렬(orthogonal matrix): 축이 서로 수직이고 길이가 1인 회전 행렬

회전 행렬의 중요한 성질:

- 역행렬 = 전치행렬

즉, 순수 회전만 있다면 역변환이 비교적 쉽습니다.

## 6. 회전 표현

### 6.1 오일러 각(Euler Angles)

축별 회전을 각도로 표현하는 방법입니다.

예:

- Pitch
- Yaw
- Roll

장점:

- 사람이 이해하기 쉽습니다.
- UI 입력에 편합니다.

단점:

- 회전 순서에 민감합니다.
- 짐벌락(gimbal lock)이 발생할 수 있습니다.

### 6.2 짐벌락

특정 각도 조합에서 두 회전축이 겹쳐 자유도 하나를 잃는 현상입니다.

의미:

- 회전 제어가 불안정해질 수 있습니다.

시험에서 자주 묻는 핵심:

- 왜 오일러 각만으로 모든 회전을 안정적으로 다루기 어려운가?

### 6.3 쿼터니언

쿼터니언은 3차원 회전을 안정적으로 표현하는 수단입니다.

보통 다음처럼 씁니다.

- `q = (w, x, y, z)`

축-각(axis-angle) 표현과 연결:

- 회전축 `u`
- 회전각 `θ`
- `q = (cos(θ/2), u * sin(θ/2))`

장점:

- 짐벌락을 피할 수 있음
- 보간이 비교적 자연스러움
- 누적 회전에 강함

단점:

- 직관성이 낮음
- 곱셈 순서 이해가 필요함

### 6.4 쿼터니언 연산

자주 나오는 개념:

- 정규화
- 켤레(conjugate)
- 역쿼터니언
- 쿼터니언 곱

단위 쿼터니언에서는:

- `q^-1 = conjugate(q)`

벡터 회전:

- `v' = q v q^-1`

여기서 벡터는 실수부가 0인 쿼터니언처럼 다룹니다.

### 6.5 회전 보간

오일러 각 보간은 예상치 못한 회전 경로를 만들 수 있습니다.

그래서 자주 쓰는 방식:

- `Lerp`
- `Nlerp`
- `Slerp`

`Slerp` 장점:

- 구면 위 최단 경로에 가까운 회전 보간

게임에서 중요:

- 카메라 회전
- 뼈대 애니메이션
- 미사일 유도

## 7. 보간과 곡선

### 7.1 Lerp

선형 보간:

- `Lerp(a, b, t) = a(1 - t) + bt`
- `t`는 보통 `0~1`

의미:

- `a`에서 `b`로 일정 비율만큼 이동

활용:

- UI 게이지
- 카메라 이동
- 색상 변화
- 네트워크 보간

주의:

- 매 프레임 `current = Lerp(current, target, dt)` 형태는 정확한 시간 기반 선형 이동이 아니라 지수 감쇠처럼 동작합니다.

### 7.2 SmoothStep

끝점에서 속도가 부드럽게 줄어드는 보간입니다.

활용:

- UI 애니메이션
- 카메라 이동
- easing

### 7.3 베지어 곡선

제어점으로 곡선을 만드는 방식입니다.

핵심:

- 직관적 제어
- 경로 설계에 유리

게임 활용:

- 카메라 레일
- UI 애니메이션
- 스킬 궤적

### 7.4 Catmull-Rom / Hermite

지나는 점 기반 곡선, 접선 기반 곡선으로 자주 등장합니다.

활용:

- 경로 추종
- 체크포인트를 통과하는 부드러운 이동

필기 포인트:

- “제어점을 반드시 지나느냐”와 “접선을 직접 지정하느냐”의 차이

## 8. 충돌 기하와 공간 계산

### 8.1 점, 선, 레이, 선분

- 점(point): 위치만 있음
- 직선(line): 양방향 무한
- 레이(ray): 한쪽 방향만 무한
- 선분(segment): 양쪽 끝이 있음

게임 활용:

- 레이캐스트
- 총알 판정
- 시야 검사
- 마우스 피킹

### 8.2 평면

평면은 보통 다음처럼 표현합니다.

- `n · x + d = 0`

여기서:

- `n`: 법선 벡터
- `d`: 오프셋

활용:

- 카메라 절두체
- 벽/바닥 판정
- 점과 평면 사이 거리

### 8.3 점과 평면 거리

점 `p`와 단위 법선 평면의 거리:

- `distance = n · p + d`

의미:

- 양수/음수로 어느 쪽 반공간에 있는지 알 수 있음

### 8.4 기본 충돌 프리미티브

필기시험에서 자주 나오는 충돌 형태:

- Circle / Sphere
- AABB
- OBB
- Capsule
- Plane
- Triangle

각 특징:

- Sphere
  - 가장 단순하고 회전에 영향 없음
- AABB
  - 판정 빠름, 축 정렬
- OBB
  - 더 정확하지만 비용 큼
- Capsule
  - 캐릭터에 자주 사용
- Triangle
  - 지형 메시의 기본 단위

### 8.5 구/원 충돌

중심 거리와 반지름 합 비교:

- 충돌 조건: `|c1 - c2| <= r1 + r2`

최적화:

- `sqrt` 없이 제곱거리 비교 가능
- `dot(d, d) <= (r1 + r2)^2`

### 8.6 AABB 충돌

축별로 겹치는지만 보면 됩니다.

2D 예:

- `a.maxX >= b.minX`
- `a.minX <= b.maxX`
- `a.maxY >= b.minY`
- `a.minY <= b.maxY`

장점:

- 빠름
- 브로드페이즈에 적합

### 8.7 SAT(Separating Axis Theorem)

분리축 정리:

- 어떤 축 하나에서라도 두 도형의 투영 구간이 겹치지 않으면 충돌하지 않습니다.

활용:

- OBB vs OBB
- 다각형 충돌

시험 포인트:

- “왜 투영해서 겹침을 보는가?”
- “후보 축을 어떻게 고르는가?”

### 8.8 바리센트릭 좌표(Barycentric Coordinates)

삼각형 내부 점 판정과 보간에 유용합니다.

활용:

- 점이 삼각형 안에 있는지 판정
- UV 보간
- 삼각형 위 높이 계산
- 내비메시 처리

### 8.9 반사 벡터

입사 벡터 `v`, 단위 법선 `n`일 때 반사 벡터:

- `r = v - 2(v · n)n`

활용:

- 튕김
- 거울 반사 방향
- 레이 반사

## 9. 카메라와 렌더링 수학

### 9.1 View Matrix

카메라 행렬의 핵심은 “월드 좌표를 카메라 기준으로 바꾸는 것”입니다.

즉:

- 카메라가 움직이는 것이 아니라
- 세상이 카메라 기준으로 반대로 움직인다고 생각하면 됩니다.

### 9.2 Projection Matrix

원근 투영에서는 멀수록 작게 보입니다.

중요 요소:

- FOV
- Aspect Ratio
- Near Plane
- Far Plane

필기시험 포인트:

- Near Plane이 너무 작으면 깊이 정밀도 문제가 커질 수 있습니다.

### 9.3 Perspective Divide

클립 공간 좌표에서 `w`로 나누어 정규화 장치 좌표로 가는 과정입니다.

이 과정을 알아야:

- 원근감이 왜 생기는지
- 왜 `w` 값이 중요한지 이해할 수 있습니다.

### 9.4 Frustum Culling

카메라에 보일 가능성이 없는 객체를 미리 제외하는 기법입니다.

수학적으로는:

- 절두체를 여러 평면으로 보고
- 객체가 그 평면들 바깥에 있는지 검사

### 9.5 법선 벡터와 조명

확산 반사 기본식 감각:

- 밝기 ~ `max(0, n · l)`

여기서:

- `n`: 표면 법선
- `l`: 광원 방향

핵심:

- 표면이 광원 방향을 얼마나 향하는지 내적으로 측정합니다.

## 10. 확률과 통계

### 10.1 확률의 기본

- 확률은 어떤 사건이 일어날 가능성입니다.
- 범위는 `0~1`

게임 활용:

- 아이템 드롭
- 크리티컬
- 강화
- AI 선택
- 매치메이킹 통계

### 10.2 기대값

기대값은 장기 평균입니다.

예:

- 10% 확률로 100골드 드롭
- 기대값 = `0.1 * 100 = 10골드`

시험 포인트:

- 기대값이 높아도 분산이 크면 체감은 불안정할 수 있습니다.

### 10.3 분산과 표준편차

- 분산: 평균 주변으로 얼마나 퍼져 있는가
- 표준편차: 분산의 제곱근

게임에서 중요:

- RNG 체감 조절
- 밸런스 분석
- 유저 행동 분포 이해

### 10.4 조건부 확률

어떤 사건이 일어났다는 조건 아래 다른 사건 확률을 보는 개념입니다.

활용:

- 특정 구간 도달 유저의 이탈률
- 매칭된 상대가 상위 티어일 확률

### 10.5 누적 분포 감각

랜덤 하나로도 확률은 정의되지만, 실제 게임은 누적 체감이 중요합니다.

예:

- “30번 시도했는데 한 번도 안 나올 확률”
- 실패 보호 장치(pity) 설계

### 10.6 가중 랜덤

아이템 드롭 테이블, AI 행동 선택에서 자주 사용됩니다.

기본 아이디어:

- 각 선택지에 가중치를 부여하고
- 누적합 구간에서 난수를 뽑습니다.

주의:

- 가중치 합이 크면 정밀도 문제를 고려해야 합니다.
- 반복 샘플링 시 편향 없는지 검토해야 합니다.

## 11. 수치해석과 실수 오차

### 11.1 부동소수점 오차

컴퓨터의 실수는 무한 정밀하지 않습니다.

따라서:

- `0.1 + 0.2 == 0.3` 같은 비교가 항상 안전하지 않습니다.

게임에서의 원칙:

- 실수는 `epsilon` 범위 비교를 고려
- 누적 오차를 경계
- 매우 큰 값과 매우 작은 값을 섞을 때 주의

### 11.2 epsilon 비교

예:

- `abs(a - b) < epsilon`

활용:

- 정규화 가능 여부
- 충돌 접촉 판정
- 값 수렴 판단

### 11.3 제곱거리 사용

거리 비교만 필요하다면 `sqrt`를 생략할 수 있습니다.

이점:

- 성능 절약
- 불필요한 루트 계산 회피

### 11.4 안정적인 구현 감각

수학 공식이 맞아도 코드가 불안정할 수 있습니다.

예:

- 0벡터 정규화
- `acos` 입력이 오차로 `1.0000001`이 되는 경우
- 매우 작은 각도에서 회전축 추정 불안정

따라서 실전에서는 종종 다음을 합니다.

- 입력 clamp
- epsilon 보호
- fallback 축 선택

## 12. 시험에서 자주 나오는 연결 질문

### 12.1 내적과 외적의 차이

- 내적은 방향 유사도와 투영 크기를 구할 때 사용
- 외적은 수직 벡터와 면 방향을 구할 때 사용

### 12.2 오일러 각과 쿼터니언의 차이

- 오일러 각은 직관적이지만 짐벌락 문제 존재
- 쿼터니언은 안정적 회전 표현과 보간에 강함

### 12.3 행렬과 쿼터니언의 역할 차이

- 행렬은 회전뿐 아니라 이동, 스케일, 전체 좌표 변환에 유리
- 쿼터니언은 회전 자체를 다루는 데 유리

### 12.4 AABB와 OBB의 차이

- AABB는 빠르지만 회전된 객체에 느슨함
- OBB는 더 정확하지만 계산량이 증가

### 12.5 왜 방향 벡터를 정규화해야 하는가

- 크기와 방향 역할을 분리하기 위해서입니다.
- 정규화하지 않으면 내적 해석과 이동 속도가 꼬일 수 있습니다.

## 13. 계산형 예제

### 예제 1. 벡터 길이

문제:

- `v = (3, 4)`의 길이를 구하라.

풀이:

- `|v| = sqrt(3^2 + 4^2) = sqrt(25) = 5`

### 예제 2. 단위 방향 벡터

문제:

- `(3, 4)`를 정규화하라.

풀이:

- 길이 = 5
- 단위 벡터 = `(3/5, 4/5)`

### 예제 3. 내적

문제:

- `a = (1, 2, 3)`, `b = (4, 5, 6)`일 때 `a · b`를 구하라.

풀이:

- `1*4 + 2*5 + 3*6 = 4 + 10 + 18 = 32`

### 예제 4. 앞/뒤 판정

문제:

- 캐릭터 forward = `(0, 0, 1)`
- toTarget = `(1, 0, 2)`
- 적이 앞쪽인가?

풀이:

- 내적 = `0*1 + 0*0 + 1*2 = 2`
- 양수이므로 앞쪽

### 예제 5. 원 충돌

문제:

- 원 A 중심 `(0, 0)`, 반지름 `2`
- 원 B 중심 `(3, 0)`, 반지름 `1.5`
- 충돌 여부?

풀이:

- 중심 거리 = `3`
- 반지름 합 = `3.5`
- `3 <= 3.5`이므로 충돌

### 예제 6. 2D 회전

문제:

- 점 `(1, 0)`을 90도 회전하면?

풀이:

- `cos90 = 0`, `sin90 = 1`
- 결과 = `(0, 1)`

### 예제 7. 반사 벡터

문제:

- `v = (1, -1)`
- 법선 `n = (0, 1)`
- 반사 벡터를 구하라.

풀이:

- `v · n = -1`
- `r = v - 2(v · n)n = (1, -1) - 2(-1)(0, 1)`
- `r = (1, -1) + (0, 2) = (1, 1)`

## 14. 고난도 개념 요약

### 14.1 법선 변환과 역전치

비균일 스케일이 있을 때 법선은 단순히 같은 행렬로 곱하면 왜곡될 수 있습니다.

그래서 법선은 보통 다음 개념으로 변환합니다.

- 모델 행렬의 선형 부분에 대한 역전치(inverse transpose)

이유:

- 법선은 “표면에 수직”이라는 관계를 유지해야 하기 때문입니다.

### 14.2 접선 공간(Tangent Space)

노멀 맵핑에서 자주 나오는 개념입니다.

기본 축:

- Tangent
- Bitangent
- Normal

이 축들로 이루어진 공간에서 텍스처 기반 법선을 월드/뷰 공간으로 변환합니다.

필기에서 직접 구현까지 묻는 경우는 드물지만, 개념 설명 문제로는 충분히 나올 수 있습니다.

### 14.3 바리센트릭과 보간

삼각형 내부의 점은 세 꼭짓점의 가중합으로 표현할 수 있습니다.

의미:

- 위치만이 아니라
- UV, 색, 높이, 법선 같은 속성도 삼각형 내부에서 자연스럽게 보간 가능

### 14.4 수치 안정성과 엔진 품질

실무에서는 “수학적으로 맞다”보다 “프레임마다 안정적으로 반복된다”가 더 중요할 때가 많습니다.

따라서 좋은 답안은 보통 다음을 포함합니다.

- 공식
- 의미
- 예외 처리
- 실제 시스템 적용 포인트

## 15. 빠른 암기 노트

- 거리: `sqrt(dx^2 + dy^2 + dz^2)`
- 내적: 방향 유사도, 투영
- 외적: 수직 벡터, 면 법선
- 정규화: 길이를 1로
- 반사: `r = v - 2(v · n)n`
- 선형 보간: `a(1-t) + bt`
- 회전 행렬은 곱셈 순서가 중요
- 오일러 각은 직관적, 쿼터니언은 안정적
- AABB는 빠름, OBB는 정확
- 실수 비교는 `epsilon` 고려

## 16. 면접/필기 답안 스타일 팁

- 공식만 쓰지 말고 의미를 한 줄로 설명합니다.
- “게임에서는 어디에 쓰이는가”를 함께 적으면 답안 품질이 올라갑니다.
- 예외 상황까지 쓰면 실무 감각이 드러납니다.

예:

- “내적은 두 벡터의 방향 유사도를 나타내며, 게임에서는 시야 판정과 조명 계산에 자주 사용됩니다.”
- “쿼터니언은 짐벌락을 피하면서 3차원 회전을 안정적으로 표현할 수 있어 카메라와 애니메이션 보간에 유리합니다.”

## 17. 마지막 정리

게임 수학은 따로 존재하는 추상 이론이 아니라, 게임 시스템을 움직이는 언어에 가깝습니다.

- 벡터는 이동과 방향
- 행렬은 좌표계 변환
- 쿼터니언은 회전 안정성
- 충돌 기하는 판정
- 확률은 게임 밸런스
- 수치해석은 엔진 안정성

필기시험에서는 공식을 외우는 것보다, **“왜 이 공식을 쓰는가”와 “실제로 어떤 문제를 푸는가”**를 설명할 수 있어야 강합니다.
