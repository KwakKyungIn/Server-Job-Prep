2-1. 서버 권위 이동 검증: 필요한 이유

클라이언트 입력은 제안, 위치 확정은 서버 책임

핵심 메시지: "이동은 클라이언트 입력일 뿐, 최종 위치는 서버가 검증 후 확정한다."

클라이언트 신뢰 시 실제 문제

1) 속도핵 / 텔레포트

비정상 delta를 반영하면 짧은 시간에 과도한 거리 이동이 가능해진다.

2) 벽 통과 / 비정상 지형 진입

충돌 지형을 무시한 좌표가 그대로 적용되면 월드 규칙이 깨진다.

3) 시퀀스 역전 / 재전송 패킷

과거 패킷이 최신 상태를 덮어써 위치 롤백이나 순간이동이 발생한다.

결과: 월드 상태 오염 → 전투 공정성 저하 → 클라이언트 간 위치 불일치(Desync)

서버 권위 설계 원칙

  • 서버가 `seq`, `dt`, `speed`, `navmesh`를 순차 검증
  • 비정상 요청은 drop 또는 clamp/slide 보정
  • 검증 완료 좌표만 월드 상태로 commit
  • 확정 결과만 AOI 대상에게 `S_MOVE` 브로드캐스트

검증 경계(제출 포인트)

  • 입력 안정성: NaN/Inf/Crazy Position 즉시 거부
  • 순서/시간: 역순 seq drop, dt 최소/최대 clamp
  • 속도: 허용 거리 초과 시 이동 거리 제한
  • 지형: NavMesh ValidateMove 통과 좌표만 반영

위협-대응 구조 다이어그램

flowchart LR
  A[Client Sends Position] --> B{Trust Client As-Is?}
  B -->|Yes| C1[Speed Hack / Teleport]
  B -->|Yes| C2[Wall Clip / Invalid Terrain]
  B -->|Yes| C3[Seq Reorder / Replayed Packet]
  C1 --> D[World State Corruption]
  C2 --> D
  C3 --> D
  D --> E[Combat Fairness Break + Desync]
  B -->|No: Server Authoritative| F[Server Validation]
  F --> G[Seq Check + dt Clamp + Speed Check + NavMesh]
  G --> H[Commit + S_MOVE Broadcast]
  H --> I[Consistent Shared World]

2-1. 이동 검증 파이프라인

코드 순서 기준: 입력 수신부터 상태 확정/전파까지의 검증 체인

검증 흐름 A (1~3 단계)

flowchart TB
  A["1) Handle_C_MOVE 수신"]
  B["RoomActor JobQueue enqueue"]
  C{"2) 입력 안정성 검사
NaN / Inf / CrazyPos"}
  D{"3) 시간/순서 검증
IsSeqNewer + ComputeDtSec"}
  E["4단계로 전달"]

  A --> B --> C --> D --> E
  C -->|invalid| X1["DROP"]
  D -->|rewind| X2["DROP"]

검증 흐름 B (4~6 단계)

flowchart TB
  P["3단계 통과 입력"]
  A{"4) 속도 검증
CheckSpeed2D"}
  B["CLAMP"]
  C["요청 좌표 유지"]
  D{"5) 지형/충돌 검증
GameMap ValidateMove"}
  E["SLIDE / CORRECT"]
  F["검증 통과 좌표"]
  G["6) 상태 확정/전파
Commit + AOI + S_MOVE + MoveStamp"]

  P --> A
  A -->|over speed| B --> D
  A -->|ok| C --> D
  D -->|blocked| E --> F
  D -->|pass| F
  F --> G

파이프라인 개요 (코드 순서 기준)

  1. 1) `Handle_C_MOVE` RoomActor Queue enqueue
  2. 2) 입력 안정성 NaN/Inf/CrazyPos 즉시 거부
  3. 3) 시간/순서 `IsSeqNewer` + `ComputeDtSec`
  4. 4) 속도 검증 `CheckSpeed2D` 초과 시 clamp
  5. 5) 지형/충돌 `GameMap::ValidateMove` 보정 분기
  6. 6) 상태 확정 Commit + AOI + `S_MOVE` + MoveStamp

분기 처리

  • 입력 오류/역순 seq: drop
  • 과속 이동: clamp 후 재검증
  • 지형 불일치: slide/correct 보정
핵심: 순차 검증으로 비정상 이동은 drop/clamp하고 확정 좌표만 공유 상태에 반영한다.
